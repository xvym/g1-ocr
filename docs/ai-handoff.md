# 给实现大模型的任务说明

状态：可供后续实施使用的交接文档；本轮只完成设计。先取得用户对共同理解的总确认及实际实施指令，再按下列阶段执行。不要把设计文件中的目标写成已经完成的功能。

## 先读与固定约束

依次阅读 [总设计](design.md)、[术语表](../GLOSSARY.md)、[执行计划](implementation-plan.md)、[数据契约](data-model.md)、[验收方案](validation.md)；按当前任务补读采集、匹配、显示专项设计与 [资源核查](resource-research.md)。ADR 记录了不可无故改动的取舍。

开始前检查真实工作区及当时有效的仓库指令。设计时用户已暂存删除 `AGENTS.md`、`.agent/EXECPLAN.md`、`.agent/PLANS.md`、`spec.md`，不得自行恢复这些旧文件或用历史内容覆盖当前设计。保护所有用户已有改动；不要把其他修改混入本任务。

- Java 8、JavaFX 8、JNA 直接系统 WGC；不维护自有采集 DLL，不改成 C#。标准 JNA/JavaFX 原生组件允许随包提供。
- 用真实 JDK 8 构建及运行，验证依赖可加载；不只设置编译目标。不使用模块系统、records、JavaFX 13+ PixelBuffer 或复制要求 Java 11+ 的示例。
- Python 只在开发/建库使用；用户运行离线包，不需要 Python、API 密钥或在线模型。
- 四作共享 OCR/公共库，红版先闭环；首版最终六类场景。不要拆四条识别管线，也不默认要求用户选版本。
- 严格字形全等；名字显式映射；数值取当前像素。共享字形不是模糊猜测。
- 沿用既有汉化，严重语义错误才修订；显示对齐不泄漏未见文本。
- 保持 98%/99.5%/300 ms 目标及已确认输入范围，不通过扩大兜底、删失败样本或重复帧计数达标。
- 未匹配必须有可归因证据，优先自动化补覆盖；不让用户逐条翻译大量缺口。

## 第一个实际任务

先完成 S0，以及 S1 的严格字形原型，建立能决定是否继续的证据。S0 交付最小 Java 8/JavaFX 8/JNA WGC 路径，S1 可独立用固定图像验证归一化。不要先制作完整外观、完整剧情库或插件化框架。

S0 需要固定工具链/依赖、记录来源、最小中文窗口和 BGRA 采集预览，实际演示遮挡、取帧、尺寸变化、最小化恢复与启停清理。JNA 没有现成 WGC 投影不构成必须自编译 DLL 的结论：按官方 ABI 补最小接口并验证。实现调用链见 [capture-interop](capture-interop.md)。

S1 需要从固定字库建立字形和等价项，用现有 16 张样本及必要可控样本验证游戏矩形、采样变换、二值化和严格命中。提交失败位置、恢复位图及原因，不能只给最终几句看起来正确的文字。

两个关卡有具体阻碍时先保存最小复现、接口/图像证据及替代选项。可继续独立任务；涉及已确认要求的变化交回讨论，不自行换语言、加业务 DLL、改模糊 OCR 或缩减输入范围。

## 分阶段任务包

每次只领取一个边界清晰的阶段任务。任务开始写明输入版本、允许修改范围、预期交付、检查方法；只有前置条件满足才进入依赖阶段。

| 任务 | 重点读取 | 必交结果与完成依据 |
| --- | --- | --- |
| S0 环境/最小采集 | technology-options、capture-interop、capture-design | 固定依赖与 ABI 来源、最小工程、真实取帧/预览及生命周期报告 |
| S1 严格还原 | matching-design、resource-research、validation | 字库生成、确定性恢复原型、逐字形报告、未命中证据 |
| S2 自动定位/完整采集 | capture-design、data-model | 自动 ROI、框选兜底、代次与有界交付、窗口几何/遮挡验证 |
| S3 公共资源构建 | resource-research、data-model、ADR 0003 | Python 可重建工具、来源清单、完整位置、宏/变量/变体、日中绑定及异常统计 |
| S4 可见匹配 | matching-design、data-model | 六场景可见区域、模板与槽位、共享输出消歧、严格未知及缺口归因 |
| S5 显示 | display-design、data-model | 区域状态机、关联组提交、相对布局、长文、暂停重试与动态回放 |
| S6 验收 | validation | 冻结清单、独立标注、各场景 N/A/C/U、延迟、失败复现与修复报告 |
| S7 发布 | technology-options、design | 配套运行时与资源包、来源/许可清单、断网及免开发工具验证、运行说明 |

S3 先选一个代表块贯通“提取→对应→片段绑定→运行包→Java 读取”，再批量扩展，不凭工作表行号自动宣告全库配对完成。标签作用域、重复 tag、缺英文桥接、终止宏和未导出工作簿是必查项。

## 每个任务的交付格式

交付说明包含：实现了什么、改动位置、输入与资源版本、运行过的检查及结果、未通过项与最小复现、对指标的影响、下一阶段是否具备条件。没有执行的检查明确写“未执行”，不要伪造全绿报告或借截图代替自动核对。

同步维护相应设计及实际 schema。新增工程细节可以按简单可测原则选择并记录；需求、译文修订门槛、采集遮挡行为、离线边界和目标指标变化必须提出证据。普通阶段任务不需要反复请求已授权的读取、可逆编辑或验证权限。

对不可重放、来源不明的“已经解决”不予验收。一次相关检查通过后，不无故扩大重复测试；新故障或变更出现时补必要验证。不要新增与当前阶段无关的框架、自动更新、在线服务或大规模人工标注流程。
