# OCR 翻译实施计划

状态：Q1–Q32 已确认两个前置验证关卡、阶段顺序、显示参数及 Java 8/JavaFX 8/JNA 直接 WGC 路线，Python 建库已确认；不维护自有采集 DLL。详细执行清单随总设计提交共同理解确认，技术路线尚未实测。本轮交付设计文档，尚未开始产品实现。

## 先验证两个主要风险

第一项是采集图片能否恢复为与原字库完全一致的点阵；第二项是当前 Windows 环境能否运行选定技术栈、可靠捕获被遮挡窗口。两项均通过后，再扩大语料生产和完整界面，避免在核心前提未成立时完成大量外围工作。这个阶段顺序已确认。

S0 与 S1 的事实探索可以独立进行；完整界面依赖已验证的识别结果与显示规则。每阶段按自身完成条件验收，不能以已有窗口界面代替识别验证，也不能以静态图通过代替实时捕获验证。

Java 部分必须由真实 JDK 8 构建和验证依赖兼容性，不能只将较新 JDK 的输出标记为目标 8。JavaFX 8 不使用模块化 JavaFX 11+ 或 PixelBuffer 等较新 API。首关优先验证单后台线程、CreateFreeThreaded 与 TryGetNextFrame 主动拉帧，以及像素缓冲和 COM 生命周期，再接入完整识别流程。不能在没有实际阻碍证据时把自编译 C++ DLL 重新设为先决条件。

## 每阶段执行清单

### S0：固定环境并证明最小采集

输入为当前工作区、已核查本机环境和 [采集接口设计](capture-interop.md)。先保存工作区状态、固定 JDK/JavaFX/JNA/Maven 版本及 ABI 来源，以真正 JDK 8 构建最小单工程。来源获取后固定 commit 与文件哈希，不需要先生成 ROM。

建立 JavaFX 中文窗口、选定 HWND、单后台线程主动拉帧、BGRA 自有缓冲和批量预览。记录帧时间/尺寸、空帧、纹理范围、窗口状态及错误；反复启停、遮挡、移动、缩放、最小化恢复，确认没有旧帧队列或明显资源持续增长。此时允许只显示采集预览，不需要 OCR 和完整界面。

交付可运行原型、准确依赖/接口清单、操作与观测记录及未通过项。源码编译通过而没有实际捕获不算完成；不把本机 Windows 11 结果推广为所有 Windows 版本通过。

### S1：证明严格字形恢复

固定日版字体、字符映射和组合规则，先核查跨资源字形是否一致，再共享配置。建立现有 16 图的矩形、字格和字形真值，结合可控字体样本测量缩放相位、采样与二值化，输出精确命中及未知位置。

报告至少包含原始裁剪、恢复点阵、目标字形、变换参数、每图/每区域失败原因。必须覆盖现有非整数放大图与普通/附加/浊点规则，不得只对已知整句查库后倒推出正确字形。与 S0 实际帧接合后补采集路径验证。

关卡通过后才扩大严格识别开发；如有已确认范围内无法恢复的样本，保留最小证据讨论输入和算法之间的冲突。

### S2：完成窗口生命周期及自动定位

将 S0 原型整理为独立捕获适配器，实现目标身份、帧池重建、有效范围、代次、资源释放及有界最新帧交付。按 [定位设计](capture-design.md)实现多线索自动候选、跟踪和重核验，再接人工框选兜底。

使用带已知 ROI 的窗口内容及真实 WGC 测试，覆盖工具栏、侧栏、内部黑区、全黑、尺寸/DPI变化和多候选；检查遮挡继续采集、最小化暂停、恢复重定位、关闭回到选择状态。交付定位误差、失败与恢复证据，不能只用框选演示替代自动定位。

### S3：贯通并扩展公共语料

按 [数据契约](data-model.md)实现 Python 提取、只读来源、中间表示、补丁覆盖层及运行包。先选有分页/变量的代表块贯通日文提取、汉化块导入、配对核查、可见绑定、Java 读取，再批量扩展。

保留工作表及标签作用域，解析控制宏与槽位，按内容合并共同模板、保留必要变体。对缺英文桥接、错误自动参考、重复标签、动态宏、中文缺口建立异常统计；大模型辅助结果必须经一致性及语义核查。交付可重建资源包、来源/许可清单、覆盖及缺口报告，不将未核查记录投入自动输出。

### S4：实现可见区域及模板匹配

在统一识别流程中逐个接入六类场景的可见区域、遮挡掩码、字形序列、行布局、变量及词表。当前帧与同页短期证据参与核验，跨页/重定位隔离；相同中文与填充值可归并，不同中文不能强选。

用静态与动态回放核对未知名字原文保留、已知名字翻译、数值取当前值、显示片段不泄漏后文。每个未命中给出归因，批量解决资源或规则问题，而非新增大量人工翻译任务。

### S5：实现完整阅读与稳定提交

用可控单调时钟验证区域状态机后接 JavaFX：新结果原子替换、150 ms 更新标记、1 秒最长暂留、真实无字 150 ms 清除、关联组一致提交。候选变化不得重置超时，UI 真正执行时再次拦截过期代次。

实现相对锚点、中文尺寸适配、换行与完整展开，以及预览、原文、暂停、重试。回放快速翻页、菜单遮挡、游标、连续 HP、恢复和长文，检查没有主动中间清空、错页覆盖或无限等数字稳定。

### S6：冻结验收并闭环修复

在最终调参前固定独立验收清单和时基；先完成小规模评测工具以便此前各阶段使用，再扩大到风险矩阵。按 [验收方案](validation.md)报告各场景 N/A/C/U、正确自动覆盖、失败原因和真实显示延迟。

失败优先修复所属模块、扩大必要资源和证据，再重放相关用例。只有目标指标及生命周期/离线边界均达到、剩余范围明确，才进入正式交付；证据不足须明确写出，不能以“功能基本完成”替代验收。

### S7：交付可离线运行的包

固定 Windows x64 配套 Java 8/JavaFX 8 运行时，将应用、JNA 标准组件、预构建资源和启动入口放入可独立运行目录/ZIP。启动明确使用随包运行时；记录来源、许可、schema 和资源哈希。

在断网及无需 Python/开发工具的环境验证启动、选窗、识别、显示、暂停恢复和退出。交付运行说明、更新资源的换包步骤、支持与未验证环境、最终指标及已知问题。未经实际发布包验证，不只提交源码构建命令就宣布用户可用。

## 建库任务要求

按工作簿、工作表、版本、完整标签和宏保留来源。先自动导入已存在的中英标签对应与日文参考，再以日版基准和 poke-corpus 核查。错误参考列、重复标签、控制码丢失、变量差异与无英文桥接内容必须进入明确的异常分类。

异常处理优先使用可重复的规则、批量一致性检查与有记录的大模型辅助。统计剩余异常数量和类型，不能默认交给用户逐条翻译。现有汉化用词保持，只有满足严重语义偏离标准才修改；补译、语义修订与显示分段分别记录。

## 验收数据要求

现有 16 张图仅作为初始回归集，不足以宣布四作全游戏覆盖。验收集需要覆盖六类场景、四作共享内容及必要变体、未见字形、动态名字与数值、滚动与逐字打印、窗口几何变化。

字库生成的可控样本用于验证字符、组合和模板边界；实际采集序列用于验证显示与窗口行为。人工或大模型辅助标注也要与实现输出分离，不能把同一段有缺陷的提取或渲染逻辑同时作为实现和唯一标准答案。

在正式调参前固定验收清单、样本数、各场景权重和计时定义。重复帧及同一内容的缩放变体分别用于稳定性和鲁棒性测试，不用于扩大语义覆盖率分母。保留每个失败样本和逐区域结果，方便后续模型复现。

## 失败时的工作方式

失败先归因到环境、定位、网格恢复、字形配置、原文资源、中文对应、变量、显示片段或提交时序。修复对应环节并重放相关用例；没有新证据时，不通过改用模糊猜字、降低指标或扩大原文兜底来宣布完成。

如果已确认的输入范围与严格匹配确实冲突，保存最小失败证据及可选调整，回到设计决策；其余独立任务可继续推进。

## 大模型任务拆分

每个任务写明读取的设计文档、输入样本、允许修改的模块、预期输出、验证方法与完成条件。阶段完成时交付代码变化、可复现检查、失败清单和文档更新，不只交付运行截图。现已形成独立的 [AI 交接说明](ai-handoff.md)，包含可直接复用的起始任务；不恢复用户已删除的 AGENTS.md 或 .agent 文件。
