# 数据契约与资源格式

状态：与总设计配套的工程默认值，供最终共同理解确认；字段尚未实现。契约优先保证可追溯、可回放和当前可见范围，具体 Java 类名可在实现中调整。

## 三层资源与标识

原始来源只读保留；Python 提取为可审计中间表示；发布时仅包含运行所需内容、来源清单及版本信息。使用 UTF-8 JSON 清单和按记录组织的 JSONL 数据，便于检查及差异对比。Java 端固定一个兼容真实 JDK 8 的 JSON 解析依赖，启动时构造只读索引；首版无需引入额外数据库原生运行库。

| 记录 | 必要字段与含义 |
| --- | --- |
| SourceManifest | sourceKey、仓库 URL、固定 commit、文件路径、文件哈希、来源用途；保留上游许可文件及发布核查结果 |
| SourceOccurrence | occurrenceId、sourceKey、游戏/语言/修订范围、文件/工作簿/工作表、全限定标签、块内序号、原始文本与控制宏 |
| TextTemplate | templateId、规范化 token、槽位定义、适用布局；共同内容共享模板，保留全部 occurrence 引用 |
| ViewVariant | viewId、templateId、可见 token 范围、行/字格布局、分页/滚动规则、必要版本差异 |
| Translation | translationId、既有中文正文与变量、基准来源或补译记录、核查状态 |
| VisibleBinding | bindingId、viewId、translationId、当前可见日文范围到中文片段的映射、槽位引用、核查证据 |
| GlyphProfile | profileId、字体来源、字格与组合规则、字形位图及别名；配置可以共享，不按游戏强制复制 |
| NameMapping | 严格日文字形键、适用名字类别、中文、明确来源、核查状态 |
| Revision | revisionId、原译引用和哈希、修改结果、严重语义问题及日文证据、检查结论 |
| BundleManifest | schemaVersion、bundleVersion、构建工具版本、所有来源版本、文件哈希、条目统计与剩余异常摘要 |

occurrenceId 从固定来源身份和完整位置生成，必须包含工作表及局部标签所属作用域，不能只用 `.Text1`。内容去重 ID 根据规范化 token 与槽位模式生成，固定算法及 schema 版本；来源更新后的迁移明确记录，不能依赖遍历顺序。

相同原文可以有多个中文来源和显示绑定。共享模板不意味着覆盖、分页和中文完全相同，去重不得丢掉这些差异。检索索引按字形序列、区域角色、行布局和槽位约束建立，不强制用户先选版本。无可见证据且中文不同的候选仍保留歧义。

## 宏、字形与可见片段

文本先保留可解释 token，例如固定字符、PLAYER/RIVAL/名字槽、十进制数槽、换行、翻页、滚动、结束与等待标记。变量声明包含类型、可见长度或格式约束、可用名字映射类别。空格、数字前导空位、价格列等按实际渲染规则表达，不能统一 trim 后丢失布局。

`text`、`line`、`next`、`para`、`cont`、`scrl`、`done`、`prompt` 等建立显式规则；`text_ram`、`text_decimal`、`text_bcd` 按具体变量解析。`text_asm` 等需读对应调用才能解释的内容，保留原始引用并报 `unsupported_source_control`，不能当作空文本静默成功。版本控制分支同样显式处理。

GlyphProfile 中每个字形记录宽高和固定长度的逐行十六进制点阵，避免把大位图写成会丢精度的 JSON 数值。区分字形标识和 Unicode 别名：`へ/ヘ` 等共享点阵时索引到同一字形。浊点、半浊点与基础字的组合、普通/战斗附加字体必须可表达并单独验证。多字符组合只有已核验规则才可拼合。

所有持久化文本区间统一用 Unicode 码点的半开区间 `[start,end)`；Python 和 Java 的字符串索引不同，Java 必须显式转换，不能把 UTF-16 下标直接写入契约。字形/token 范围采用自身序号，不能与字符区间混用。

ViewVariant 表达当前实际能看到的部分，包括滚动时保留的上一行及被菜单遮挡后的可用字格。VisibleBinding 指向中文正文的有序片段和槽位，可保持措辞作分段、拼接；不能从完整段落绑定推出尚未显示的后文。若无法安全分段，报 `alignment_gap` 并改进建库，不默认展示全文。

对齐核查至少检查：日文可见范围、中文含义范围、固定专名、变量次数/类型、条件与操作结果、分页之后的内容是否泄漏。既有译文的语义修改必须走 Revision；缺失内容的补译单独记来源，不伪装成对齐。

## 构建流程与异常输出

1. 固定来源，生成清单；按块解析日版及中文工作簿，保留原内容和完整位置。
2. 建立候选对应：优先使用已核查结构和文本证据，poke-corpus 与英文只作桥接；中文工作表自动匹配列仅是候选。
3. 校验控制宏、槽位、名字、版本与语义；批量处理不一致并保存规则/大模型辅助记录。
4. 建立可见片段绑定，输出未覆盖、歧义和对齐缺口；按场景统计，不隐藏异常。
5. 生成运行包和精确索引；验证全部引用、范围、哈希及 schema，可重建同一内容。

补丁作为上游之外的覆盖层保存，包含目标记录、预期旧哈希、操作、原因、证据和检查状态。旧哈希不符必须停止应用该补丁，避免来源更新后误修其他文本。运行包只纳入完成核查的对应，未核查记录计入资源缺口报告。

汉化工作簿按“工作簿＋工作表＋完整标签块”读取，不将 I 列日文或 J–M 自动参考逐行视为真值；`_G1RB.json` 不是完整总库，重复 tag 和未导出文件要保留异常。详细已知陷阱见 [资源核查](resource-research.md)。

## 运行时帧与区域

| 对象 | 必要信息 | 所有权与校验 |
| --- | --- | --- |
| CapturedFrame | sessionId、targetIdentity、captureGeneration、frameSeq、sourceTime100ns、取帧/复制完成的本地单调时间、有效宽高、stride、BGRA 缓冲 | 来源时间的时基、单位及校准方式显式保存；Java 自有副本复制完成才发布；释放后不可复用读取；有效内容不能超过纹理或缓冲边界 |
| GameGeometry | geometryGeneration、窗口内容内游戏矩形、原生网格变换、定位状态、核验证据、人工/自动来源 | 原生坐标 160 × 144；状态不足时不提交新 OCR 结果 |
| RegionObservation | observationSeq、完整代次组合、regionKey、groupKey、contextGeneration、可见字格掩码、行/字形、槽位、游标属性、失败原因 | 同一关联组字段来自同次有效观测；保留未知位置，不伪造原文 |
| MatchCandidate | 模板/视图/绑定引用集合、当前中文、槽位填充值、输出等价键、完整性与核验证据 | 等价键包含可见范围、中文及填充值；来源 ID 不要求唯一 |
| ViewSnapshot | 当前代次及序号、区域正文、原文、相对矩形、状态、首次不一致时间、提交时间 | 原子交给 UI；不是每帧全部清空重建 |

targetIdentity 不只保存可复用的 HWND 数字，还保存进程与本次绑定身份。切换目标或重开窗口产生新 session；重建帧池、恢复与重新定位使相关代次递增。识别结果回到提交器时校验代次和序号，JavaFX 实际应用快照时再校验，过期直接丢弃。换代失效与 UI 应用必须有明确先后关系，不能只在后台入队前检查。按防闪规则保留已显示旧视图与允许旧任务新提交是两回事。

regionKey 表示本页布局中持续存在的区域角色和位置；布局换代后重新关联，不以单独像素坐标永久标识。groupKey 表示同次提交的关联区域，如 PC 父子菜单。数值动画可独立更新槽位，但关联数字、名称、单位不能从不同帧随意拼接。

持久的显示状态与有限页面上下文分开：识别上下文在切页/几何失效时清理；旧的完整视图可继续按防闪时限暂留。旧视图只供展示，不能反向证明新页已经匹配。静止画面缺少新 WGC 帧不等于无文字，可由有效快照和窗口存活信息确认状态；重复帧不伪装成新的独立识别证据。

## 状态、队列与诊断

观测状态至少区分 `MATCHED`、`INCOMPLETE`、`UNKNOWN_GLYPH`、`AMBIGUOUS`、`RESOURCE_GAP`、`EMPTY`、`INVALID_FRAME`。显示状态区分正常、过渡暂留、更新中、等待、暂停；EMPTY 必须来自有效游戏定位和真实无字区域，采集失败不能当作清空信号。

跨线程只交付自有缓冲或明确引用计数的只读对象。最新帧槽有界，覆盖旧待处理项时释放其资源；最新视图提交合并排队，停机清理资源及未消费对象。不要逐像素跨 JNA，也不要为每个区域无限添加 `runLater`。

区域状态机除帧输入外接收单调时钟定时事件，无新帧也执行 150 ms 标记/清除和 1 秒到期。完整快照的核验不强制依赖两个新 WGC 帧，具体终止及稳定证据见 [显示设计](display-design.md)。

诊断记录资源版本、样本/会话定位、时间、代次、模板候选、字形未命中位置、状态转移和失败码。失败图像/裁剪证据只在本地按容量上限保留，确保可重放；相同故障聚合统计，避免每帧生成一个人工工单。发布默认值及离线边界见 [总设计](design.md)。
