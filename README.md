# 宝可梦 G1 日版 3DS VC 实时 OCR 翻译

Windows 本地工具：直接获取 `new3ds_view` 或 `cc3dsfs` 投屏窗口中的日文，在独立 JavaFX 窗口显示有据可查的中文汉化文本。

处理流程：整数倍画面 → GB 160×144 → 固定文字区域 → 100ms 采样、连续 3 次相同 → 像素 OCR → 本地汉化匹配 → 对话或列表显示。

## 开发入口

- [Spec](pokemon_g1_vc_ocr_SPEC.md)：唯一产品需求、七类目标、技术边界与验收标准。
- [ExecPlan](execplan.md)：从 S0 开始的实施步骤、目录约定、交付物与完成条件。
- [AGENTS.md](AGENTS.md)：修改范围、简单实现、验证与动态测试授权规则。
- [素材说明](testpic/README.md) / [截图索引](testpic/manifest.csv)：原始截图、候选样例与证据边界。
- [日文文本档案](testpic/labels/japanese.md) / [标注说明](testpic/labels/README.md)：108 张逐图日文答案；当前要求目标区域原始日文识别 100%，中文标注及最终中文验收条件待定。

## 首版使用条件

- Windows 10 1903 或更新版本 / Windows 11，x64。
- 3DS 上屏，VC 日版《宝可梦 红、绿、蓝、皮卡丘》，原生 1:1 显示，投屏按点对点整数倍输出。
- 目标为主对话、战斗操作、战斗技能、背包道具、PC 道具、PC 宝可梦列表和商店购买商品七类区域。
- 要求窗口遮挡后仍可捕获；最小化时允许暂停。具体投屏软件和游戏版本的支持声明须有相应实机证据。
- 普通用户使用包含运行时和原生 DLL 的交付包，无需安装开发工具。

像素短时稳定只决定何时尝试 OCR；绘制中途停顿可能提前触发，后续变化后重新识别。未可靠识别、译文存在实际冲突或显示条件不足时保留日文/未知状态，不猜测译文。

## 日中映射语料（S4 建设中）

顶部“译文字号”可用上下箭头调节（12～36，默认20），即时应用到对话和列表译文并自动换行；本次运行期间保留，重启恢复默认。

顶部“简洁模式”仅显示对话及列表两个文本框，拖动中间分隔条调整占比；“拆分文本框”可将两者放到独立窗口，通过标题栏移动、窗口边缘缩放。在任一译文框内右键可调字号、拆分/合并或退出简洁模式，也可复制、全选。关闭列表独立窗口会自动合并；退出简洁模式恢复完整界面及原窗口位置/尺寸，关闭主窗口退出应用。布局切换保留当前内容及字号，重启恢复默认完整界面。

[CSV 资源与用法](src/main/resources/corpus/README.md) 已固定四版本日文及用户选定的仿日版中文来源，包含完整文本、名称词条、战斗组合模板、变量和显示控制关系。10,205 条记录已建立来源对应或明确组成/未引用状态；中文原始单元格保留不改。

已保存多页/滚动对白的中文语义分段，并修复 23 条记录的来源漏接或错配。另有 9 类、23 条来源记录的语义差异已按用户确认处理，补译、订正及接受的汉化增省文均保留原汉化与决定。23,957 个可见行窗口中，23,806 个保存当前相交单元的完整中文范围，3 个只有省译礼貌语，6 个阻止已知语义错译，141 个通过组合处理，1 个源码明确未引用。显示完整语义单元不要求日文最后一行或起始行均被观察到；建设计数不代表运行时命中率或最终中文验收通过。静态资源见 [建库状态](reports/text-corpus.md)，当前实现与验证见 [中文运行时](reports/chinese-runtime.md)。

同文译文清单的T001～T041已按用户确认统一显示译文，保留各来源、原汉化和后续对白；T042暂缓。包括“嗨～！未来的冠军！”等问候不再因这批措辞差异产生不同的保存译文。当前编译/打包和静态检查通过，动态输出待验证，详见[同文统一记录](reports/translation-merge-review.md)。

## 当前开发版本（0.3.0，中文运行时已接入，实机验收暂缓）

此前商店资源快照的全部 108 张已完成中文离线测试（后续姓名查库变更未重跑）：95 张全单元就绪、2 张部分输出、6 张无中文、5 张无目标。25 组开发场景的 40 次比较及 13 张图片的 29 个固定预期全部通过。野生和捕获物种名误当昵称的问题已修复，コラッタ 显示“小拉达”，捕获成功的 ビードル 显示“独角虫”；四天王等已匹配语义单元可以直接显示完整中文。商店购买列表现可识别商品、原价和选中行，保留底部对白；战斗操作、战斗技能、商店、背包及共享PC列表直接在选中项前显示 `▶`，不再显示类型标题或选中序号；原108图新增4行商店目标后为206行、2237 token，用户另附商店图单独验证通过，见 [商店验证](reports/shop-items.md)。原汉化把“研究化石”写成“研究宝可梦”的单元继续阻止显示，具体订正待确认。逐图结果和待处理项见 [全图中文验证](reports/chinese-images.md)，就绪不代表全量中文语义验收通过。

沿用实时捕获、自动校准与像素 OCR，优先配置为 **new3ds_view，仅上屏**。中文/状态和原始日文分别显示，无需确认或选择游戏版本。匹配器联合全部语料；来源唯一或全部候选当前中文、变量及显示条件一致时发布保存的译文，并保留全部来源。实际冲突、字符前缀未完成、缺当前变量或语义错误时保留日文。数量、等级与选择位置保留；宝可梦名及昵称（含 PC 列表和战斗）优先采用物种译名，无物种对应时再查全部独立词条；玩家、NPC 和复用玩家名保持全部独立词条查询规则。所查询的词条组有唯一中文或全部同译才替换，未命中或多译冲突则保留该变量原文。例如宝可梦名/昵称 `ゴースト` 显示“鬼斯通”，属性中的同文仍为“幽灵”。来源和已批准修订可在详情中查看。

本机现有运行文件已就绪，提供两个双击启动入口，共用 Java、应用 JAR 和捕获 DLL 检查：

- **普通模式：`run-live.cmd`**。发起应用启动后命令窗口自动关闭，应用独立运行，不写入或清空日志文件；文件检查或创建进程失败时保留控制台错误。
- **Debug 模式：`run-live-debug.cmd`**。保留命令窗口直至应用退出，并等待按键关闭；标准输出和错误分别保存到 `output/live-stdout.log`、`output/live-stderr.log`，每次 Debug 启动覆盖日志。应用非零退出码会显示错误提示，具体原因查看错误日志。

启动后选择 new3ds_view 窗口，点击“开始”，无需选择游戏版本。PowerShell 用户可执行 `./run-live.ps1` 启动普通模式，或 `./run-live.ps1 -DebugMode` 启动 Debug 模式。

点击顶部“识别历史”，或在任一译文框内右键选择“识别历史（最近10条）”，可回看最近10条原始日文、当时译文及未翻译原因。历史覆盖对白、战斗操作、技能、道具等全部识别区域，每次稳定识别一个区域计一条，新记录在前；光标移动、重复刷新及切换玩家名后的重译不重复记入。左侧选择记录，右侧文字可复制；新记录到来不会跳离仍在列表内的当前选择，所选记录被淘汰后转到最新。历史在停止、重新校准和切换界面后仍保留，仅本次运行有效，不写文件，也不用于识别或补译。

顶部“当前玩家”下拉框可指定本次识别使用的玩家名，旁边提供“添加／修改／删除”。填写游戏中的日文原名（例如 `サトシ`），中文沿用现有词库，无对应或多译时保留原名。添加后自动选中新名字，修改作用于当前名字，删除当前名字后恢复“自动识别（未指定）”。名单和当前选择保存在 `config/player-names.json`，重启后恢复，个人配置不提交到版本库；保存失败会提示本次更改仅在当前运行生效。

下拉选项和当前选中值同时显示日文与中文，例如 `グリーン（青绿）`、`サトシ（小智）`；词库多译时并列并标明“多译”，无对应时显示“暂无译名”。识别与保存仍使用日文原名，添加/修改时也只填写原名。

首次使用自动加入四版本词库收录的11个默认玩家／对手名字：`レッド`、`サトシ`、`ジャック`、`グリーン`、`シゲル`、`ジョン`、`ブルー`、`ツネカズ`、`ジャン`、`ヒロシ`、`イエロー`。已有名单首次升级时补入缺少的名字，保留当前选择；此后修改或删除的默认名字不会在重启时自动补回。默认仍为自动识别，需自行选择对应名字。

当前画面明确识别到的玩家名优先；画面缺少玩家名时，使用下拉框所选名字，再使用本会话已确认的名字。选中 `サトシ` 后，“カンナとの／しょうぶに かった！”可使用“小智”补足原译文；原始日文和候选当前变量不改写。切换选择会刷新当前稳定文字的译文，无需等待画面变化或重新做 OCR；诊断标明“使用所选玩家名”或“沿用前文玩家名”。手动选择在停止、重新开始、校准及捕获重置后保留，自动记忆会清除；切换存档时请自行选择对应名字或恢复自动模式。自动识别不会修改手动名单。本项动态及界面效果待验证。

0.3.0 的 Java 编译、中文开发场景和 108 张日文回归证据见 [中文运行时](reports/chinese-runtime.md)。原生 DLL 与 WGC 构造窗口的历史验证仍属于 0.2.0，见 [编译运行验证](reports/live-validation.md)。真实 new3ds_view 验收按用户要求暂缓；两种投屏软件、真实时序、当前 JavaFX 界面交互及端到端延迟均未验收。人工检查表见 [实时开发记录](reports/live-development.md)。需要重新构建时，本机已有工具链，可执行：

## 离线入口与 0.1.0 验收基线

已提交的 0.1.0（`0107e12`）对全部 108 张固定截图通过原始 OCR 验收：202 行、2186 个字符 token，CER=0，全图正确率 100%。按用户确认，仅四组完全同形假名等价比较，并保留候选；严格 Unicode 结果另列为 95/108。详见 [历史验收报告](reports/japanese-acceptance.md)、[0.1.0 逐项结果](reports/japanese-0.1.0.json) 及 [布局证据](reports/layouts.md)。当前版本的回归证据见 [最新逐项结果](reports/japanese-all.json)。

开发工具链固定为 Amazon Corretto JDK `21.0.9.10.1`（Windows x64）、Maven `3.9.16`、JavaFX `21.0.8`。0.2.0 主窗口启动及 JNI/WGC 历史集成证据见编译运行报告；0.3.0 的构建与离线验证见中文运行时报告。离线运行不加载捕获 DLL，不需要 Python、网络或标注。

本机开发 JDK 放在被忽略的 `.tools/jdk21.0.9_10/`；其他环境设置 `JAVA_HOME` 指向 JDK 21，并让 `mvn` 可执行即可。固定 JDK [下载地址](https://corretto.aws/downloads/resources/21.0.9.10.1/amazon-corretto-21.0.9.10.1-windows-x64-jdk.zip)，ZIP SHA-256：`77226707f66b0c19a5baeb2c176ff5cc1c7d0f2a9f67f52354ce2901a53b9240`。正式自带运行时的用户包属于 S6，本次尚未交付。

```powershell
# 构建并运行固定图片集、必要几何/构造时序回归（须在获授权范围内使用）
./build.ps1

# 单张离线识别：输入 PNG、上屏原点 ox/oy、整数倍率 k、输出目录
& ./.tools/jdk21.0.9_10/bin/java.exe -jar target/g1-ocr-0.3.0.jar `
  'testpic/Screenshot 2026-10-20 21-22-46.png' 0 0 3 output/example
```

输出为 `gb.png`、原始 `crop.png` 和 `ocr.json`，包含原始日文、footer、选择位置、字形诊断，以及独立的 `translation` 匹配/显示状态、候选、中文与来源。`equivalent` 表示多个来源的当前结果一致，不能解释为只命中一个来源。离线入口只有上述五个参数，无游戏版本参数。`0 0 3` 仅适用于这批截图。单图不携带滚动前文，也不代表真实稳定性或实机验收。

`./build.ps1 -Group development` / `-Group holdout` 可按固定同源分组运行；默认 `all` 始终比较全部 108 张。构建缓存和输出写入 `.tools/m2/`、`target/`、`output/`，不改系统 Maven 配置。字库可用 `tools/import_font.py` 从固定上游重建；资源再分发条件仍待确认，见 [来源说明](src/main/resources/SOURCES.md)。
