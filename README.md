# 宝可梦 VC 初代日版实时 OCR 翻译

一个从零开发的 Windows 本地工具：识别 **3DS VC 日版《宝可梦 红、绿、蓝、皮卡丘》**投屏画面的日文，在独立窗口显示**当前可见内容**的中文翻译。技术目标为 **Java 8 / JavaFX 8 / Maven / Windows 10 x64**。

> 当前状态：**未开始开发**。此包仅包含开发规范，不含源码、测试程序、录像、Ground Truth 或已通过的验收结果。

## 唯一的离线录像素材

离线动态测试**仅使用用户已有的 4 段 3DS 实机原始录像以及游戏截图**。可以只读引用旧项目 `testpic/video/` 中的实际文件，或原样放入 `data/raw/video/`（加入 `.gitignore`）。**不要求重新录制或补录，也不使用其他视频替代**。

开发开始后，首先核对四个原文件的实际路径、SHA-256、时间戳、画面、游戏版本与真实会话关系；不能凭文件名推断内容。由四段录像选择代表性的**连续帧片段**，保留片段内的全部原始帧、时间和异常状态。未选择的区间或缺失的场景/版本标为**未验证**。

测试用的 **Ground Truth（GT，独立核验的标准答案）**必须从原始画面独立核对并在 OCR 运行前冻结。没有额外视觉/OCR/语言模型，并不意味着 GT 可以无人工核查地自动变成正确答案；无可靠核验时应保持**待验证**，不能伪称通过。用户无须参与日常标注。

## 使用 Codex 从零启动

1. 将本压缩包按原目录结构解压到**新项目根目录**，保留 `.agent/` 文件夹。
2. 确保 Codex 能够读取现有 **4 段录像**的真实路径（可直接引用旧项目；不必复制），并告知其路径。没有实际文件时先登记缺失，不能编造验证结果。
3. 让 Codex 读取 `AGENTS.md` → `spec.md` → `.agent/PLANS.md` → `.agent/EXECPLAN.md`，从 **M0** 开始。
4. 每个阶段先产生可复现证据，再更新 `.agent/EXECPLAN.md`；只按该文件的“下一步”继续执行。

可复制的首次指令：

> 请阅读 AGENTS.md、spec.md、.agent/PLANS.md、.agent/EXECPLAN.md，从 M0 开始按 Spec + ExecPlan 模式开发。离线动态测试只使用我已有的 4 段实机录像；先核对原件和时间轴，再建立不依赖额外模型的独立 Ground Truth 与连续帧回放验证。不得继承旧进度，未实现命令不得当作成功结果。

## 开发顺序与边界

**工程 → 录像索引/连续帧测试 → 独立 GT → 日文 OCR → OCR 验收 → 中日语料 → 翻译/UI → 真实环境验收**。不从中文译文反推 OCR；产品无需模型、3DS 内存访问或 ROM 修改。FFmpeg/FFprobe 可作为开发期录像解码工具。

四段录像可以覆盖的范围取决于其真实内容。最终的真实窗口后台/遮挡采集、实际 UI 延迟和长时间稳定性需另作运行测试，但**不要求为此再录新的视频**。
