# PLANS｜ExecPlan 编写与恢复规范

本文件**只规定计划如何编写和执行**，不重复产品要求。`spec.md` 定义要求及验收，`AGENTS.md` 定义执行边界，`.agent/EXECPLAN.md` 是唯一不断更新的执行计划和进度来源。全文路径均相对于**项目根目录**。

## 1. 基本原则

- **自包含**：离开聊天记录也能恢复工作；写清起点、输入、位置、具体命令、预期结果、验证方式及阻塞时的替代动作。
- **先定义验证，再编码**：每一阶段先约定输入与证据，再做实现和检查。可以改变技术步骤，但不可降低 spec 的范围或门槛。
- **只有证据才能勾选**：源码写完、合成测试通过、工具退出 0 与独立真实数据验收是不同状态；未知/冲突/输入缺失为“待验证”。
- **只更新一份进度**：进度、决定、问题次数和恢复位置都保留在 `EXECPLAN.md`；无必要不拆子计划。
- **离线输入边界**：计划中的视频素材只来自用户既有的 4 段实机录像；依 spec 按真实会话及连续帧建立、冻结并验证 GT。未选时段和覆盖缺口不计作通过。

## 2. EXECPLAN 必备章节

| 章节 | 最少写什么 |
| --- | --- |
| Purpose / Big Picture | 目标行为与本轮范围 |
| Context and Orientation | 文件、目录、输入限制与术语 |
| Plan of Work | 阶段依赖、产物、完成条件 |
| Concrete Steps | 下一步和计划命令；命令未实现要显式注明 |
| Validation and Acceptance | 输入/评分范围、分母、证据与判定链接 |
| Idempotence and Recovery | 重跑是否安全、失败如何恢复/撤销 |
| Artifacts and Notes | 输出路径、报告与版本身份 |
| Interfaces and Dependencies | 模块边界、外部工具及前置条件 |
| Progress | 勾选清单：已完成 / 未完成 / 待验证分开 |
| Surprises & Discoveries | 观察、异常、证据；不要写成猜测 |
| Decision Log | 选择、理由、日期和影响 |
| Outcomes & Retrospective | 实际成果、限制、未解事项与最新恢复指令 |

可使用短段落、表格和命令块，**不必为每个任务重复填写模板**；每个里程碑至少能找到：输入、步骤、产物、验收方法、失败恢复。初始进度**全部未完成**。

## 3. 执行与状态变更

1. **开始/恢复**：按 `AGENTS.md` 规定依次完整阅读 `spec.md`、`.agent/PLANS.md`、`.agent/EXECPLAN.md`。核对实际文件与版本，再从最新“下一步”处理最早可推进的未完成任务。
2. **实施**：小步实现并验证；记录实际命令与结果。计划中的命令必须标“**计划接口/尚未实现**”，不能用它作为既有工具证据。
3. **记录**：每个实质性改动后更新 Progress、发现、决策、结果/下一步，注明时间、文件/输入哈希、构建或数据版本、报告位置。
4. **修复**：保存失败证据 → 最小修复 → 目标用例和相似用例 → 回归。相同问题默认最多 **3 次**，不同会话恢复不清零；预算/依赖不足时停下该问题并继续无依赖工作。
5. **范围变更**：修改标注/片段/GT 时保留旧版本、原因及差异；冻结验收预期不能按被测 OCR 输出篡改。验收材料进入调参后转为回归材料，不能继续称独立验收。
6. **结束**：给出下一次无需猜测即可执行的一个动作、其前置条件、预期产物与检查方法；无可执行工作时如实记录阻塞，不承诺后台自行继续。

## 4. 录像验收特别要求

计划应分别说明：**4 个原媒体 → 全量帧/PTS 账本 → 按覆盖矩阵预选连续片段 → 真实历史热身/评分区间 → 代理原图双遍核读 → 用户审阅批准 → GT 冻结 → 原时间轴回放 → 比较/回归**。测试消费者只能看图像、尺寸、时间和正常配置，不能读 GT、clip 身份或评分标签。

人工卡点遵循 `spec.md §3.4`，优先于“转做无依赖工作”的一般恢复规则。ExecPlan 必须记录审阅批次、范围、材料路径/哈希、待审/退回/获批状态及用户批准依据；等待期间不得冻结 GT、运行被测管线或继续其他开发。恢复前核对批准版本与当前材料一致；实质变更重新提交，不能将用户对流程的同意记作对未来标注的批准。

选定评分片段应 **100% 帧/时间/可见状态机会覆盖**；不能用定时抽样掩盖单帧事件。真实会话无法隔离时，应保留开发和回归结果，但独立验收标待验证。四段录像外的游戏覆盖与真实窗口验收按 spec 单独报告，不要求补录。

## 5. 变更范围

用户只要求更新文档时，只修改文档、检查路径/术语/约束是否一致并交付文档；**不得因此自行开始开发**。用户明确要求开发时，遵循当前 `EXECPLAN.md` 的恢复位置，按能实际执行的步骤推进。
