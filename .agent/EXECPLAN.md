# EXECPLAN｜从零开发与恢复记录

> **状态：尚未开始。** 本文件是**唯一**进度与恢复记录，按 `.agent/PLANS.md` 维护（本文路径均以项目根目录为基准）。下文命令属于**计划接口**，除非后来记录实际实现和测试证据，否则一律不能认为可以执行或已经通过。

## Purpose / Big Picture

从零开发 Windows 10 x64 / Java 8 / JavaFX 8 本地程序：识别 3DS VC 日版《宝可梦 红、绿、蓝、皮卡丘》投屏画面中的当前日文，在独立窗口展示对应中文。研发顺序为**录像验证体系 → 日文 OCR → OCR 验收 → 中日关联 → 翻译/UI → 真实环境验收**。

**离线动态测试只允许用户现有 4 段原始实机录像**；不要求重录/补录，不添加其他视频代替。以全帧可追溯、先独立核验 Ground Truth（GT）、后冻结并回放比较为核心，不引入额外视觉/OCR/语言模型。不继承旧工程、帧索引、答案或测试结果。

## Context and Orientation

当前项目仅提供 `README.md`、`spec.md`、`AGENTS.md`、`.agent/PLANS.md`、`.agent/EXECPLAN.md`，**没有**源码或工具，也没有已经实现的命令。

| 将来创建的位置 | 用途 |

| `config/input-videos.json` | **恰好 4 段现有录像**的只读路径清单，初始需用户提供或在可访问旧目录核对 |

原视频优先只读引用原 `testpic/video/` 目录；如原路径不可用，可把**同样四个原文件**原样置于 `data/raw/video/` 并忽略版本控制。不得假定录像在此包中；未读取的文件不得猜版本、帧率或场景。

术语：**原媒体**=四段视频文件；**clip**=从原媒体选取的连续帧区间；**warmup**=重放真实前史但不评分；**scored range**=冻结后逐帧计分区间；**GT**=独立于主 OCR 的正确可见内容/边界；**page opportunity**=一次完整页面可见机会。未选片段、未知标注、会话无法隔离等记为**待验证**。

## Concrete Steps

### M0（第一个实际动作）

1. 在新的空项目中按最小结构创建 Maven/Java 8/JavaFX 8 工程，确定可复现依赖、构建与 Windows 运行条件；将 `data/raw/` 排除在版本控制之外。
2. 为**恰好 4 个现有原始视频**建立 `config/input-videos.json` 路径登记；只读访问文件。已知旧路径 `testpic/video/` 只是候选，必须核对真实文件名与数量；找不到则记录缺失，不创建假文件。
3. **工程建立后**执行 `mvn test`，保存执行结果、JDK/Maven 版本、提交与报告。**本包未执行该命令。**
4. 进入 M1，先查实输入，再处理 PTS/帧索引；**不要跳到 OCR 或中文**。

### M1–M2（先建设可靠基准）

1. 对四视频单独计算 SHA-256，保存 FFprobe 的流信息和逐帧**整数 PTS、time_base、duration**；使用固定解码参数生成 RGB 帧哈希，核验重复解码结果及异常帧。`PTS × time_base` 才是来源时间，不假设固定帧率。
2. 对**实际出现**的对话、战斗、背包、状态、PC、商店和逐字加载/短页/滚动/清屏/光标/黑帧/缩放等建立覆盖矩阵。**先看原画面、后定 clip**；clip 必须有事件前后文与评分区间，所有原始连续帧保留。只对选段独立全文核读，不要求全视频全文标注。
3. 核实四文件是否属于相互独立的会话。优先以会话划分 development/regression/acceptance；若不能隔离，则记录“不具备独立验收集”，仍允许开发与回归。
4. GT 第一遍按原帧盲读，第二遍重新核对并用**独立画面像素/布局扫描**排查遗漏；逐项处理一帧显示、浊点、数值、文字/时间边界和空帧。**不能使用主 OCR/翻译输出作为预期**。
5. 冻结之前核对评分范围内**100% 原帧/时间/可见状态**，拒绝 `unknown/unreviewed/conflict`、空集、错误源哈希、缺帧、时间洞与泄漏。冻结文件不可就地改写；保存依据、版本与 SHA-256。
6. 单 clip 与原会话顺序按原始 PTS 回放。测试驱动读取 GT 比较，**程序只看到正常图像/时间**；漏识别、迟到、提前译文和异常均保存前后原帧。失败素材不得从已经冻结的分母移除。

### M3–M7（在可靠基准上开发）

- **M3**：日版来源字库 → 原始字格 OCR → 视觉处理（阴影/浊点/缩放）→ 当前可见状态；先在 development 上迭代并保存 regression。
- **M4**：独立会话验收（条件足够才判定）→ 原始字符/整页 → 最终整页/关键字段/空画面 → 时间和错误分析；将调参过的验收材料降为 regression。
- **M5**：M4 通过后，建立日文消息与固定显示页面的可重建分母，核对中文来源、分页及变量角色；未核对中文不计覆盖。
- **M6**：精确/受约束模板匹配、场景/历史消歧、实时翻译及 JavaFX 独立窗口；未知时显示原文，失效时删除旧结果。
- **M7**：独立中文 GT、原时间轴验证、实际 UI 呈现/消失观测、真实投屏后台/遮挡、两种 2 小时稳定性；按 spec 逐项提交报告。

## Validation and Acceptance

以 `spec.md §4` 为**唯一数值验收定义**：原始 OCR 字符 ≥99.5%、整页 ≥95%；最终 OCR 100%、空画面误报 0；中日两类覆盖分别 ≥95%；独立中文/端到端正确 100%；实际显示/移除 ≤200ms；四视频循环原速及真实投屏各 ≥2h。不可提前放宽或只看平均值。

每次报告至少含**四个原视频身份、选段/评分范围、帧/页面机会分母、真实会话隔离、GT 冻结哈希、构建/数据版本、实际输出与失败数、未选范围/版本/场景缺口**。真实窗口与实际 UI 延迟单独报告。无独立验收会话或核验能力时记录“待验证”，不删除原有失败机会也不补录新视频。

## Idempotence and Recovery

原视频始终只读，工具再跑应保留相同帧顺序、整数 PTS 和像素哈希；若输入或解码器参数变化，生成新账本版本，旧账本保留供比较。GT 仅以新版本修订并记录差异、依据和受影响回归。首次执行失败不清理原件、不重置已经累计的问题次数、不把失败或待验证改成通过。

恢复按以下顺序：查看本文件最新“下一步” → 核对文件/证据和 hash → 执行最早有前置条件的未完成工作 → 运行最小相关验证与回归 → 更新日志。对同一问题默认最多 3 次有证据的修复尝试；达上限或外部输入缺失时停止该问题，继续无依赖工作，不能假设新材料会自动出现。
