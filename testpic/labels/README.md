# 日文标注与验收口径

- [japanese.md](japanese.md)：108 张图片的可阅读文本档案，每条链接回原图。
- [japanese.json](japanese.json)：同一批独立答案，供后续离线比较使用。
- [原始素材索引](../manifest.csv)：样本 ID 与原 PNG 的对应。

## 标注来源与使用边界

使用模型直接查看原图中的目标文字并转录。标注状态 `model_visual_transcribed` 表示模型目视标注，不表示人工复核，也不表示产品 OCR 已通过；不使用待测产品输出来生成或修正答案。档案可作为本阶段固定比较基准，发现标注错误时须回到原图核对后修正并更新版本，不能为迁就程序输出改变答案。

本批包含全部 108 张图片：103 张含目标文字，5 张无目标文字或只有空框。共 109 个区域记录、206 行目标文字（含附属退出框）；没有把地图、启动菜单、空框和转场样本从索引中剔除。精确游戏版本不从人物名字或截图内容推定。

记录七类目标区域的可见文字，包括商店购买商品名和价格。战斗名称/HP 面板、技能 PP/属性框、PC 操作菜单/盒子编号、启动菜单、余额及商店操作/数量专框正文等专门布局不纳入本批目标。范围外界面中仍可见的主对话继续纳入；出售时使用的背包道具列表仍按背包布局纳入。用途不确定但网格明确的共享列表必须继续 OCR，不因语义标签待定而跳过。

## 文字约定

- 保留原图可见行、日文大小假名、清浊点、标点、长音、数字与字段顺序，不按熟悉的台词补字或纠错。
- 数字记为 ASCII；各行首尾的排版空白去除，连续空白格记为一个 ASCII 空格。只允许上述字形/排版等价处理，不能删除实际字符差异。
- 两个三点字形记为 `……`；引号按可见字形转录。Unicode 组合清浊点可统一为 NFC，不改变文字。
- PC 列表中呈 `:L` 形状的等级字形统一记为 `<Lv>`，按一个字形 token 统计，后面的等级数字必须准确。它是字形记号，不代表从脚本推断的隐藏信息。
- 经用户确认，字库完全同形的四组「り/リ、へ/ヘ、べ/ベ、ぺ/ペ」允许等价比较，OCR 必须保留全部候选；独立答案保留原先的日文写法。报告另列未经同形字等价处理的严格 Unicode 指标。只允许这四组，不推广到相似字形或语义近似。
- 箭头、光标和边框不计入文字。`selected_row` 从 0 开始；选择信息与文字分别检查，不因指针移动要求正文重做 OCR。
- `footer_lines` 是目标列表附属退出框的文字，例如“とじる”，同样必须识别。
- 只显示到“きず”“きゅうしょ”“ゆけっ”等片段时，档案保留片段，不补齐句尾、标点或变量。
- `regions: []` 表示没有目标区域；`empty: true` 表示目标框存在但无文字。两者都不得产生目标文本。
- `uncertainties` 用于明确记录不能从图像确认的字符；有未解决项的样本保持待核对，不能静默移出分母或用模型推测记为正确。

## 当前阶段通过条件

所有 108 张图片均须产生一条验收结果；同屏多个目标区域分别比较，不可只挑其中一个。以规范化后的纯视觉 `rawOcr` 与档案比较：

1. 所有目标文字与 `footer_lines` 逐字一致，字符错误率 `CER=(替换+删除+插入)/标注字符数=0`。
2. 全图完全正确率达到 `108/108=100%`。漏区域、漏字、多字、错字、未识别字符及空框/负样本误输出均不通过；不能用总体平均值抵消个别图片失败。
3. 可见名称、数量、等级和正文数值必须识别；被遮挡的字符、范围外面板及后续未显示文本不得补出。
4. 词典或语料纠错后的 `resolvedJapanese` 单独报告，不能替代原始 OCR 达标。语义用途标签未定不得阻断已确定网格的文字比较。
5. 中文标注、预期中文、中文覆盖范围和通过门槛均为待定项。本阶段没有中文答案不阻塞日文验收；日文通过也不代表最终中文翻译通过。

这批固定样本的 100% 不外推为新图片、四版本全覆盖或实时效果达到 100%。动态测试按 [开发规则](../../AGENTS.md) 的授权范围执行；建立文本档案及静态数据核对不等于运行产品 OCR。
